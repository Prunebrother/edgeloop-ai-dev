# F2.7 — Configurable Event Intelligence

## Audit and architecture

Baseline `415d57f` (`f2.6.1-checkpoint`) had one validated BrowserObservation stream, a twelve-sample/fifteen-second trend buffer, snapshot freshness (five seconds), strict source/epoch/session validation, bounded original events and duplicate suppression. Original engine counter/status transitions alone prove edge, selection, milestone and Came Early events. F2.5/5.1 Director already supplies bounded queues, user priority, selection debounce, TTL and cooldowns; F2.6 provides fallible per-model narrative excerpts/epochs; F2.6.1 provides atomic local Director settings and character drawers. No detector, provider or dialogue can control the engine.

F2.7 extends that same buffer to **512 samples / 180 seconds**, without a new ingestion path. The canonical F2.3 trend view remains the last twelve samples in its original fifteen-second/at-most-five-second-gap segment. Longer detector windows have distinct derived provenance. Source/status/session changes, missing/stale data, reconnects and invalid timestamp order break measurement continuity. Duplicate timestamps never create samples. Held simulator sliders do not become invented repeated measurements; replay explicitly supplies timestamped synthetic readings and observation heartbeats.

The CPU-only registry emits versioned `DerivedEvent` records separately from canonical original events. Fields include stable ID, kind/detector, category (`authoritative`, `derived`, `scheduling`), source/simulation flag, session, first/last/creation timestamps, endpoint levels/change, reference value/kind, unit, actual supporting span/count, quality, narrative significance, evidence and configuration revision. User detectors cannot emit Critical observations; original safety priority remains fixed. Endpoint levels for rapid changes are medians of three actual readings at each end, not single potentially noisy samples. A mathematical observation never establishes a physiological cause, diagnosis or emotion.

## Detector defaults

All values are narrative software settings, **not medically validated thresholds or EdgeLoop safety settings**. Common minimum is five distinct valid samples, maximum source gap twelve seconds, cooldown 120 seconds, hysteresis four BPM. Rapid rise/fall use 15 BPM over a 30-second window with at least 20 seconds of evidence and confirmation at the final three readings. Sustained elevation requires every reading in a thirty-second tail (within sixty seconds) to exceed its explicitly labeled reference by 15 BPM. Resting configuration is labeled a setting, not a measured baseline; a narrative-only reference or earlier measured median may be selected. Return toward reference requires an earlier measured baseline outside its current window, a confirmed prior elevated state and a sustained decrease toward that reference; it is not clinical recovery. Fluctuations use three-reading medians, at least nine samples and three reversals of ten BPM over at least thirty seconds within ninety seconds. Stable intervals are OFF by default; when enabled, a forty-five-second interval must stay within four BPM. No smoothing is used to fabricate sustained samples.

Original milestones/configuration changes reuse existing validated transitions. Quiet intervals are scheduling opportunities, never HR facts. Detector latches require a reset condition plus cooldown before another emission. The user-supplied sparse example has insufficient samples for default rapid windows. A repeatable forty-second/five-sample configuration is included in replay, with eight-BPM hysteresis for fall/return; exact emitted evidence is saved with evaluation.
